# WebDAV / NAS 配置

在声桥的「设置」中填写 WebDAV 入口、账号、密码。主同步目录默认填写 `/shengqiao`，Obsidian 转写目录默认填写 `/obsidian/小米录音`，两者均可修改，缺失目录在检测连接或同步时自动创建。

目录路径相对于所填 WebDAV 入口的根目录。例如地址为 `https://nas.example.com/dav/` 时，默认输出到 `/dav/shengqiao/` 和 `/dav/obsidian/小米录音/`，后者独立于主同步目录。地址必须是 WebDAV 入口，不是 NAS 管理后台或网页登录页面。Obsidian 目录字段填写同一 WebDAV 下的路径，复用同一账号和密码。升级保留用户已配置的目录，不会因默认值变化悄悄迁移旧文件。

建议为声桥单独建立有读写权限的 NAS 账号或应用密码。密码使用 Android Keystore 加密后保存在本机，应用不收集账号信息。HTTPS 使用系统证书验证；不会忽略证书错误或跟随可能泄露凭据的重定向。可信内网确需 HTTP 时，可显式勾选允许 HTTP。

密码框默认隐藏，可点输入框内部右侧的小眼睛核对明文，再点一次隐藏。图标随状态切换，触控区域为 48dp；切换保留输入内容及光标位置，不会自动保存或修改密码，重新进入设置页默认隐藏。

支持 HTTP Basic、HTTP Digest 和匿名访问。Digest 自动按服务器挑战协商，支持 MD5、SHA-256、SHA-512-256 及其 sess 变体、qop=auth（含旧式无 qop）；qop=auth-int-only、OAuth 和网页验证码登录尚不支持。Basic 应配合 HTTPS 使用。Digest 在目录检查阶段协商，文件流上传不盲目重放；上传中认证 nonce 失效会保留失败状态，重新同步时再次协商。

点击「测试连接」使用当前输入的地址和账号密码，分别验证两个目录的登录、自动创建、写入、MOVE、HEAD 长度、GET 正文读回和 DELETE 清理；任何一项失败都会显示失败原因，不会仅凭服务器可访问就报告成功。检测不会自动保存输入的凭据。服务器必须支持 `PROPFIND`、`MKCOL`、`PUT`、`MOVE`、`HEAD`、`GET` 和 `DELETE`。若入口发生 301/302 重定向，请直接填写最终地址。

0.3.1 直接检查目标目录，不再强制先访问 WebDAV 根目录，也不对已有目录发送 MKCOL。目录检查为 404 才创建，创建返回 409 时补建缺失父目录再重试；仅访问已存在的共享目录时不要求列出父目录。

连接失败会标明「主同步目录 / Obsidian 转写目录」、HTTP 方法、具体路径、状态码，以及服务器声明的认证方式（如果有）。例如 `MKCOL /dav/shengqiao/：认证未通过（HTTP 401），服务器要求 Digest 认证`。401 不是“目录不存在”的证据；需结合失败方法判断认证、路径授权、代理或服务器策略。显示信息不含密码、Authorization 原文、nonce 或响应正文。

0.3.2 将结果拆为「认证、目录检查 / 创建、文件写入、文件移动、文件读回、测试文件清理」，分别显示通过、失败、未确认或未执行。目录 PROPFIND 被 401 拒绝时明确显示「认证失败，尚未执行创建」；写入通过但 MOVE 被拒绝时保留已通过的步骤。主目录未通过时 Obsidian 标为未执行，避免误以为两个目录都检测过。目标目录操作通过表示该操作获准，不独立证明服务器对所有路径都强制校验凭据；403 或其他无法确认认证的结果不会冒充认证通过。

设置页的「查看诊断日志」可查看最近一次检测。日志仅保存在应用私有目录，最多保留 200 行，每次新检测替换旧检测；包含阶段、实际请求方法和路径、HTTP 状态、耗时、服务器声明的认证方案及请求异常类型，不包含密码、Authorization、完整认证挑战或响应正文。检测结果和日志可选择文字复制。按钮在检测期间禁止重复发起，避免多个检测结果互相覆盖。

目录结构：

```
shengqiao/
  .shengqiao-index.json    # 一键同步使用的远程增量缓存索引
  <稳定录音 ID>/
    当前录音名.mp3          # 或 m4a/wav 等原始格式
    metadata.json          # 标题、录音时间、时长等
    当前录音名.txt          # 正文、说话人、段落时间
    当前录音名.transcript.json # 原始分段及逐字时间轴
    当前录音名.summary.txt  # 有摘要时生成
    manifest.json          # 最后写入的完成标记与各部分摘要
obsidian/
  小米录音/
    202610/
      10.13客满沟通会.md
    .shengqiao/             # Markdown 身份、同步凭据和改名恢复记录
```

稳定 ID 与文件名无关；兼容旧版的 ID 和目录，不因改名另建目录。标题同时保存在 metadata 和 manifest 中。

## Obsidian Markdown（0.3.0）

主目录内的 TXT/JSON 保留，另将有转写的录音导出成 UTF-8 Markdown。以录音标题为文件名，按录音创建时间（北京时间）的 `YYYYMM` 分组，创建时间同时兼容秒和毫秒格式。缺少日期时进入「日期未知」，不冒充当月录音。没有转写的录音等待后续补传，不生成空笔记。

Markdown 包含录音标题、真实录音时间、时长、摘要（如有）和完整转写，顶部属性包含 `shengqiao_id`、`recorded_at`、`recorded_month` 和 `source`。这些属性可供 Obsidian 按真实录音时间倒排，详见 [Obsidian 排序说明](OBSIDIAN.md)。

改名时通过 MOVE 移动旧 Markdown，再更新标题和正文；月份纠正也会移动原笔记。`.shengqiao` 内保存按稳定录音 ID 关联的凭据和移动恢复记录，避免中断后重复创建。不要手动删除这些恢复记录。同月同名的不同录音或已有用户笔记会采用附稳定 ID 的文件名，保留现有文件。

两个目录均完成才显示「已同步」。Markdown 失败会显示同步失败，重试时复用主目录已完成的音频。只修改 Obsidian 目录会触发 Markdown 补同步，不重传主目录音频；旧目录副本保留。导出的 Markdown 由小米录音内容驱动，下一次源更新会覆盖对该导出文件正文的手工修改，个人补充建议单独写笔记。

## 改名与内容判重（0.2.0）

在小米录音机改名后，声桥下一次「刷新录音」更新本地标题，「一键同步」会先刷新，再自动重命名远程音频、转写和摘要文件，无需手动导入或手动修改远程文件。

- 用实际文件 SHA-256 判定内容相同，文件名不参与身份判断。转写先按小米 `recordSha1` 与来源记录配对，再归入声桥的稳定录音 ID。小米来源标识变化而实际内容相同时，沿用原 ID、已有转写和所有目标服务器的同步记录。
- 首次刷新读取实际音频计算摘要；后续仅在路径、大小、修改时间或来源标识变化时重新计算。改名导致路径变化也会重新核对摘要，修改时间变化但摘要相同也不会重新上传音频。同名但内容不同的录音保存在各自的稳定目录内。
- 同一内容出现多条来源记录时，优先采用可读、已知的来源，再按时间选择，在 APP 内保留一条内容记录。文件名包含路径分隔符或 NAS 不支持字符时会替换并附短摘要，超长标题也会缩短；文件名用 UTF-8 URI 编码传输，支持中文、空格、`#` 和 `%`。
- 远程改名使用 `MOVE`，不会以复制或重新上传音频代替改名。先写 `.rename.json` 恢复记录，原文件经过临时名称移动到新名称，验证原名消失、新名大小正确，再提交完成标记并移除恢复记录。转写内容没有变化时同样只移动原文件。
- 断网、退出或移动成功但响应丢失时，下次同步先恢复上次改名；连续改名先恢复上次任务，再应用最新名称。支持只改变英文字母大小写的改名。远程目标同名文件被占用时停止并报错，`Overwrite: F` 防止覆盖。
- 升级保留原 SQLite 记录及各目标的同步凭据；旧版 `audio.ext` / `transcript.txt` / `transcript.json` / `summary.txt` 下次同步通过 `MOVE` 迁移为当前录音名，不重新上传相同音频。`metadata.json` 与 `manifest.json` 是固定协议文件，更新其中的标题和文件路径。

同步需要声桥和 Shizuku 读取服务可用；当前为用户点击后执行，不是对录音机持续实时监听。保留声桥应用数据，才能保留来源标识变化前的本地身份映射；清除数据后不保证能找回来源标识已经改变的旧远程目录。

音频上传时会计算实际文件的 SHA-1 和 SHA-256。小米的数据库 sha1 用于关联录音与转写，实测部分录音的这个标识与当前文件 SHA-1 不同，所以它与文件校验摘要分开保存。通过临时文件上传，再 `MOVE` 到最终名称，并核对服务器报告的文件大小。每条录音完成后写入 `manifest.json`；批量同步或单条手动同步结束时，再原子更新主目录的 `.shengqiao-index.json`。

远程增量索引按稳定录音 ID 保存远程目录、标题、来源标识与修改时间、音频 / TXT / 转写 JSON / 摘要 / metadata / manifest 文件名、各内容 SHA-256 和字节数、转写可用状态、Obsidian Markdown 路径与指纹，以及完成时间。索引不复制转写正文。一键同步会先刷新本地录音 / 转写清单并核对本地文件状态，再只读取一次远程索引；索引完全匹配的录音不会进入同步队列。任一记录、文件名或内容摘要变化、或索引中缺少该录音时，才进入原有逐项核对流程，并只重传变化或缺失的文件。任务结束会报告索引命中数和实际进入增量同步的数量。旧版本没有索引时，第一次同步会读取现有逐条 manifest，完成后生成索引；中断后下次可从 manifest 恢复并补齐。

中断时保留已完成部分，重试从未完成文件重新上传，当前版本不做单文件分块续传。网络突然中断可能留下隐藏的 `.upload-<UUID>` 文件，NAS 管理员可按时间清理这些未完成临时文件。

逐项核对时，主目录 TXT、转写 JSON、摘要和 metadata 按 UTF-8 字节数检查；与音频、Obsidian Markdown 一样，缺失或长度不符时整文件重传覆盖，不从远程已有字节位置续写。正式名称固定。写入先进入 `.upload-<UUID>`，上传流结束并核对字节数后 MOVE 覆盖正式名称，再核对远程大小；主目录 manifest 最后发布，主目录和 Obsidian 均完成后才记录本地完整成功。

APP 被系统杀死后不会自行恢复后台任务，重新打开后点击同步会扫描、核对并继续处理；已确认完整的文件可复用，未确认或大小不符的文件从头上传。上传完成但 manifest 尚未提交的音频也可能重新完整上传，以保证重试安全。上传期间杀进程可能遗留隐藏临时文件，它们不作为正式文件或成功凭据使用。

校验边界：索引是声桥已完成上传的远程收据，用于快速识别本地内容变化；WebDAV 没有通用的服务器内容 SHA-256 接口，完全匹配的记录不会每次逐个读取远程文件。因此，若有人在 NAS 上手动删除或改写文件但保留索引，应用无法仅靠该索引发现变化，也不能自动识别远端同大小损坏。上传时仍会计算源 SHA-256、核对上传流和 WebDAV 报告的长度；HTTPS 提供传输层完整性保护，但不代表 NAS 落盘后做过独立 SHA-256 复核。

没有转写的录音可以先上传音频，手机显示「音频已同步 · 待转写」。源音频不可用、转写暂未配对、删除记录不会被悄悄当作“全部成功”。不会自动删除手机录音或 NAS 副本。

首次使用需要安装、启动官方 Shizuku 并允许声桥。可通过 USB 启动，不要求无线调试；服务运行后，声桥自动连接，首次授权成功会继续刚才的任务。非 root 手机重启后可重新通过 USB 启动，也可自行选择无线调试。Shizuku 13.6 官方增加 Android 13+ 连接可信 WLAN 时免 root 自动启动，但本机重启自动启动尚未验证。

## 录制、转写进行中的刷新与同步（0.3.4）

- 已结束但尚无转写的录音先同步音频，显示「音频已同步 · 待转写」；部分转写可以先保存。以后再次刷新、同步时只更新新增或变化的转写、Markdown 和元数据，音频内容没变就不重传。
- 文件最近 5 秒内仍在写入、读取期间发生变化、或单条暂时不可读时，该条显示暂缓同步，其余录音继续处理。停止变化后下次刷新自动重新核对；不因一条不稳定文件中断整批扫描。
- 小米 AsrService 的常驻前台通知不再被一概视为正在录制 / 播放。真机确认该通知曾在录制结束后保留，旧判断因此拦截了两个按钮共用的扫描流程。
- 真正录制 / 播放期间，声桥不执行可能打断录音机的系统备份，使用上次成功保存的录音清单和转写，核对其中稳定的文件并同步。缓存清单中的音频若大小或已验证修改时间变化会跳过；当次刷新明确提示使用上次清单。**正在录制期间的新录音、新标题和新转写不会通过系统备份即时取得，需结束录制后再刷新。** 首次使用尚无清单时，也需要结束录制后完成首次读取。该限制避免为了导出元数据而停止用户的录音。
- 点击后立即显示「刷新中…」和当前阶段，可停止任务；失败会弹出原因，首页可查看最近一次刷新 / 同步日志。刷新日志与 WebDAV 连接检测日志分别保存在应用私有目录。

## 开发验证

配套测试服务仅监听本机，不公开到网络：

```
python3 -m venv /tmp/shengqiao-webdav-env
/tmp/shengqiao-webdav-env/bin/pip install WsgiDAV==4.3.3 cheroot==10.0.1
mkdir -p /tmp/shengqiao-webdav-test
/tmp/shengqiao-webdav-env/bin/wsgidav --config tools/test-webdav.json --server cheroot
adb -s <真实手机序列号> reverse tcp:18765 tcp:18765
```

测试账号仅用于 USB 本机回环服务，见测试配置，不能用于公开部署。真实 NAS 尚需使用用户自己的地址与凭据进行联调，不能把回环测试等同于特定 NAS 已验证。

仅允许 Digest 的测试配置为 `tools/test-webdav-digest.json`，启动方式相同。Basic 和 Digest 测试配置使用同一端口，需分别启动，不能同时运行。
